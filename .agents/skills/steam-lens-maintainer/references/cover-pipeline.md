# 封面异常：定位与最小修复

## 当前状态

用户实际反馈过部分封面异常，v1.1 已修改加载链路。还没有逐款真实 CDN 验证。未知具体 AppID 时，不把历史说明、演示图或合成 PNG 当作异常游戏证据。

## 数据路径

```text
Steam appdetails 中完整图片 URL
  → server.safe_steam_image / normalize_app
  → headerImage / capsuleImage / capsuleImageV5
  → app.js normalizeGame
  → live/import/localStorage/JSON 往返
  → coverCandidates
  → coverMarkup
  → CoverLoader
  → 卡片与详情图片布局
```

演示库未保存官方图片字段，可能仍靠有限推算路径；旧版采集记录也可能缺字段。只刷新有问题的游戏以补齐数据，不要清空全部游戏库或收藏。

## v1.1 的实现约束

- 完整官方地址先加入候选，包括 hash 子目录、区域文件名和查询字符串；其次替换 Steam CDN 主机名但保留路径，最后才是有限旧式路径。
- `safeSteamImage` 与 `safe_steam_image` 允许对应 AppID 的受限 Steam 图片地址；旧 HTTP 可升级 HTTPS。拒绝非允许主机、用户名密码、脚本 URL、危险端口和其他游戏的 AppID。
- 候选去重，最多 12 条。单源 4,500 ms，整轮 18,000 ms。不能把两个限制误改为无限尝试。
- 成功源记忆 30 分钟，失败记忆 45 秒，仅当前页面会话。手动重试立即清除对应失败记忆。缓存键是候选 URL 集，不是全局固定一张图。
- `IntersectionObserver` 懒加载；probe 图片成功后才进入可见 DOM。清理旧请求与定时器，迟到响应不能覆盖新图；离开 DOM 的卡片不能继续不断尝试备用源。
- 1×1 等错误像素不能算成功；现有阈值拒绝宽 <160 或高 <60 的图片。
- 卡片/详情容器比例 920:430，`object-fit: contain` 完整显示；不同图片比例可留白，不能默认拉伸或裁掉标题。窄屏有单列规则。
- 全部失败有名称占位和“重试封面”；关闭封面设置后不发封面请求。重试按钮不能误触发详情或更改收藏。

这些域名和路径只代表现有候选策略，不保证每个候选当前存在；新增资源格式/域名要基于实际响应和来源验证，不放宽到任意站点。

## 复现记录

记录 AppID、地区、数据模式、浏览器/视口、`file://` 或本机 HTTP、是否旧缓存、三项官方图片字段、最终候选列表和实际被尝试地址。避免把 Cookie、访问令牌或其他私密请求头放进报告。

区分以下故障层级：

1. **字段缺失**：原始 appdetails 有地址但标准化/保存/恢复丢失，或旧数据从未采集过地址。
2. **地址校验**：合法新格式被拒绝。先保存脱敏样本，再最小扩展校验，并补恶意 URL 反例。
3. **资源与网络**：404/403/429、DNS/TLS 错误、超时、错误内容类型、解码失败。浏览器跨源 `<img>` 不一定能暴露 HTTP 状态；无法获得时如实记录，不要编造“404”。
4. **加载器**：懒加载没启动、失败缓存遮挡恢复、切换后串图、旧计时器继续工作、备用源重复。
5. **布局**：图片已成功但宽高、父容器、占位层、透明度/层叠或 object-fit 设置导致异常。

本机服务的数据采集成功与浏览器 CDN 图片成功是两条链路，应分别检查。先排查原因，不把关闭所有图片或给所有游戏套同一张占位图当作修复。

## 最小回归

新增测试先失败后通过，并覆盖受影响环节；同时运行现有 `test_covers.py` 与 `test_frontend.py`。改后端字段或 URL 校验时还要运行 `test_server.py`。

关键场景：主源成功；主源失败备用成功；全失败可重试；超时与迟到响应；快速搜索/排序/详情切换；移除卡片停止；关闭封面不请求；同 AppID 验证；JSON 往返；桌面与窄屏无溢出、不裁切。

真实验证应使用少量明确 AppID，并遵守上游限流。网络不可用时仍可验证逻辑和布局，但结论只写“离线测试通过，真实资源待验证”。
